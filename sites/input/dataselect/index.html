Datastructure

The datasets (e.g. devices) come from the FROM clause. Every dataset names its collection (e.g. the table with the measured values) in the attribute data_collection.
When the user selects a dataset, Dataselect loads the definition of that collection over the Model and offers its attributes. With SmartData the definition comes from the database. For a JSON file the definition is read from a file named definition.json in the same folder:


{
    "attributes": [
        {"name": "id", "type": "int8"},
        {"name": "ts", "type": "timestamp"},
        {"name": "temperature", "type": "float8"}
    ]
}

If the collection has an attribute named like the option defaultTimeAttr (ts), it is used as time attribute without asking. Otherwise a third selectbox lets the user choose it.

Share the selection as link

Dataselect keeps the URL up to date with the selection, without reloading the page. Besides the dataset (parameter oo_id, see option urlParam) it reads and writes the parameters attribute, start and end (format 2026-11-25T00:00). Unknown datasets and attributes are ignored, an invalid date keeps the preset period. With urlParam null nothing is read or written.


anomalies.html?oo_id=9&attribute=temperature&start=2026-10-26T00:00&end=2026-11-25T00:00

Example 5: Select several datasets

With the option multiple several datasets can be selected with checkboxes in a dropdown. Only attributes that all their collections have are offered. The selection delivers all datasets in sets, each with a filter for collections several datasets share (option filterAttribute). The URL holds the ids separated by commas.
